# Πλάνο Αποθήκης -- Fagron Hellas

Next.js 15 (App Router, στατικό export) + Supabase, δημοσιευμένο στο
GitHub Pages: **https://gpapachs.github.io/fagron-whs/** Έκδοση "online" του εργαλείου διαχείρισης
παλετοθέσεων -- ίδιος σχεδιασμός/λειτουργίες με πριν, plus:

- **Σύνδεση με κωδικό** -- καμία σελίδα δεν δείχνει δεδομένα αποθήκης χωρίς
  λογαριασμό Supabase Auth (το ίδιο επιβάλλεται ξανά και στη βάση με Row
  Level Security, ώστε ένα bug στο frontend να μην μπορεί ποτέ να το
  παρακάμψει).
- **Ιστορικό/audit log ανά θέση** -- κάθε αλλαγή κατάστασης/προϊόντος/
  ποσότητας/σημειώσεων καταγράφεται αυτόματα από trigger στη βάση (πίνακας
  `position_history`), όχι από τον κώδικα της εφαρμογής -- δεν μπορεί να
  παρακαμφθεί ούτε από χειροκίνητη επεξεργασία, ούτε από το import Excel.
  Φαίνεται μέσα στο πάνελ κάθε θέσης ("Ιστορικό αλλαγών").
- **Γρήγορη αναζήτηση / barcode scanner** -- το πλαίσιο πάνω-πάνω δέχεται
  σκανάρισμα από τους περισσότερους barcode scanners χειρός/tablet χωρίς
  καμία ρύθμιση (λειτουργούν σαν πληκτρολόγιο: γράφουν τον κωδικό + Enter),
  και λειτουργεί εξίσου καλά για γρήγορη χειροκίνητη αναζήτηση.
- Ζωντανή συγχρονισμένη προβολή -- αν δύο άνθρωποι έχουν ανοιχτό το πλάνο,
  η αλλαγή του ενός εμφανίζεται στον άλλον αμέσως (Supabase Realtime).

Οι 799 πραγματικές θέσεις (12 διάδρομοι + ειδικές θέσεις) και η 2Δ/3Δ
προβολή, η αναζήτηση προϊόντος, τα φίλτρα κατάστασης και το import από
Excel παραμένουν ακριβώς όπως ήταν.

## 0. Δημοσίευση (GitHub Pages)

Κάθε push στο `main` χτίζει και ανεβάζει αυτόματα την εφαρμογή
(`.github/workflows/deploy.yml`, καρτέλα **Actions** στο GitHub). Το Supabase
URL και το anon key είναι μέσα στο workflow -- είναι δημόσια εκ σχεδιασμού.

Η εφαρμογή είναι στατική (δεν υπάρχει server): ο έλεγχος σύνδεσης γίνεται
στον browser (`components/auth/AuthGate.tsx`) και τα δεδομένα τα προστατεύει
η βάση με Row Level Security -- χωρίς σύνδεση το Supabase δεν επιστρέφει
τίποτα.

## 1. Supabase

1. Δημιούργησε ένα project στο [supabase.com](https://supabase.com) (αν δεν
   το έχεις ήδη).
2. **SQL Editor -> New query**: τρέξε ολόκληρο το
   `supabase/migrations/0001_init.sql` (πίνακες, RLS, trigger ιστορικού,
   realtime).
3. **SQL Editor -> New query**: τρέξε ολόκληρο το
   `supabase/migrations/0002_seed_positions.sql` (γεμίζει τις 799
   πραγματικές θέσεις -- τρέξε το ΜΙΑ φορά, `on conflict do nothing`
   οπότε δεν πειράζει αν τρέξει ξανά κατά λάθος).
3b. **SQL Editor -> New query**: τρέξε ολόκληρο το
   `supabase/migrations/0003_repack.sql` (σελίδα Ανασυσκευασίας --
   προδιαγραφές, απόθεμα, δικαιώματα). Μπορεί να ξανατρέξει χωρίς πρόβλημα.
4. **Authentication -> Users -> Add user**: φτιάξε έναν λογαριασμό για κάθε
   άτομο που θα δουλεύει με το πλάνο (email + κωδικός -- δεν υπάρχει
   δημόσια εγγραφή, μόνο εσύ προσθέτεις χρήστες). Κάθε νέος χρήστης παίρνει
   αυτόματα ρόλο `staff`· αν θες κάποιον `admin`, τρέξε στο SQL Editor:
   `update public.profiles set role='admin' where email='...';`
5. **Settings -> API**: αντίγραψε το `Project URL` και το `anon public` key
   -- πάνε στο βήμα 2 παρακάτω. Δεν χρειάζεται πουθενά το `service_role`
   key -- η εφαρμογή δεν το χρησιμοποιεί καθόλου, ό,τι κάνει περνάει μέσα
   από τα ίδια RLS policies είτε από το πρόγραμμα περιήγησης είτε από τον
   server.

## 2. Environment variables

Αντίγραψε το `.env.example` σε `.env.local` και συμπλήρωσε τις δύο τιμές
από το βήμα 1.5 (και στο hosting που θα διαλέξεις, αν διαφέρει).

## 3. Τοπική εκτέλεση

```bash
npm install
npm run dev
```

Άνοιξε http://localhost:3000/fagron-whs/ -- θα σε πάει στη σύνδεση.

## 5. Ανασυσκευασία (`/repack`)

Υπολογίζει τι μπορεί να ανασυσκευαστεί με το τρέχον απόθεμα συστατικών και
από ποιες θέσεις μαζεύονται.

1. **Προδιαγραφές** (μόνο `admin`): ανέβασε την εξαγωγή συνταγών του ERP
   (γραμμή τελικού κωδικού `71-…` και από κάτω οι γραμμές συστατικών με
   ποσότητα ανά τεμάχιο). Γραμμές με `#` στον κωδικό (υπο-συστατικά ενός
   κιτ) αγνοούνται -- συλλέγεται το κιτ. Αν ο ίδιος κωδικός υπάρχει δύο
   φορές, η δεύτερη κρατιέται ως εναλλακτική «(2)». Κάθε ανέβασμα
   αντικαθιστά ολόκληρη τη λίστα.
2. **Απόθεμα** (κάθε χρήστης): ανέβασε την εξαγωγή αποθέματος του WMS
   (στήλες `Θέση`, `Περ.Θέσης`, `Είδος`, `Περ.Είδους`, `Ποσ1`, `ΜΜ1`).
   Ίδιο είδος στην ίδια θέση (πολλές παρτίδες) αθροίζεται. Αντικαθιστά το
   προηγούμενο απόθεμα για όλους.
3. Η σελίδα δείχνει:
   - **μέγιστο ανά κωδικό** -- πόσα βγαίνουν αν γίνει μόνο αυτός, ποιο
     συστατικό είναι ο περιορισμός, και ποιοι κωδικοί μοιράζονται συστατικό
   - **χειροκίνητο πλάνο** -- ποσότητες ανά κωδικό, έλεγχος επάρκειας
     συνολικά (με τα κοινά συστατικά), «Μέγ.» = όσα βγαίνουν ακόμα με ό,τι
     περισσεύει από το υπόλοιπο πλάνο
   - **λίστα συλλογής** ανά θέση (εκτύπωση με κουτάκι ✓ ή Excel)
4. Με τα κουμπιά «Περιοχές αποθέματος» εξαιρείς περιοχές (π.χ. εισερχόμενα)
   από τον υπολογισμό. Το πλάνο και οι περιοχές θυμούνται στον browser.

Ο ρόλος `admin` χρειάζεται για τις προδιαγραφές:
`update public.profiles set role='admin' where email='...';`

## Επόμενα βήματα / γνωστοί περιορισμοί

- Ο κώδικας γράφτηκε χωρίς δυνατότητα σύνδεσης στο API του Supabase από το
  περιβάλλον όπου αναπτύχθηκε -- έλεγξε προσεκτικά τη σύνδεση, την
  αποθήκευση μιας θέσης, το ιστορικό, την αναζήτηση/barcode και το import
  Excel πριν το δώσεις στην ομάδα.
- Ο ρόλος (`admin`/`staff`) υπάρχει ήδη στη βάση και φαίνεται στο πάνω
  μέρος της σελίδας, αλλά προς το παρόν κάθε συνδεδεμένος χρήστης έχει τα
  ίδια δικαιώματα επεξεργασίας -- αν θες π.χ. οι `staff` να μην μπορούν να
  αδειάζουν θέσεις ή μόνο οι `admin` να κάνουν import Excel, πες το και
  προσθέτουμε το περιορισμό στα RLS policies και στο UI.
- Deploy/hosting: το αναλαμβάνεις εσύ -- η εφαρμογή είναι ένα κανονικό
  Next.js project, οπότε δουλεύει σε Vercel ή όπου αλλού τρέχεις Next.js,
  αρκεί να ορίσεις τα δύο environment variables του βήματος 2.
